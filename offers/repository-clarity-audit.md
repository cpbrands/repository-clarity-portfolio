# Repository Clarity Audit

A fixed-scope review for maintainers who need to know whether their repository documentation matches the project people actually receive and run.

## Outcome

You receive a verified map of what is current, what is stale or contradictory, and which documentation repairs will reduce onboarding and maintenance friction first.

## Fixed package

**Price:** USD $149  
**Turnaround:** 3 business days after scope confirmation  
**Repository:** One small public repository, or one agreed documentation area in a larger repository

## Included

1. Pin the review to an exact commit on the default branch.
2. Audit the README and up to five agreed documentation files against observable repository evidence.
3. Test one documented installation or quick-start path in a disposable environment when it is safe and practical.
4. Check links, commands, paths, version references, configuration claims, and duplicated or conflicting instructions.
5. Deliver a concise evidence-backed report with prioritized findings and clear limitations.
6. Prepare one documentation-only pull request correcting up to three agreed findings, with no more than 300 changed lines.
7. Include one revision after maintainer feedback.

Every finding identifies the file or command inspected, the observed result, and whether the conclusion is confirmed or still uncertain.

## Best fit

This package is useful when:

- Users report that setup instructions no longer work.
- Product behavior changed faster than the README or guides.
- Documentation is spread across several files with no clear starting point.
- A release, handoff, or public launch needs a fresh-eyes verification pass.
- Maintainers want a bounded audit before commissioning a larger rewrite.

## Not included

- Application feature development or source-code repair
- Production deployment or access to live customer systems
- Penetration testing, security certification, or compliance approval
- Database migrations or infrastructure operations
- A full documentation-site rewrite
- Verification that requires undisclosed credentials, paid infrastructure, or unsafe external effects

If the repository is too large for this package, I will propose a smaller target area before work begins.

## What I need from the maintainer

- Repository link and target branch
- Intended reader or user
- The most important setup, usage, or handoff path
- Any known documentation pain point
- Confirmation of the exact audit scope
